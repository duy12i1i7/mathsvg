# Mathematical specification

## 1. Values and evaluation

The normative evaluator operates on finite typed vectors:

- `Bytes(n)`: \(n\) octets;
- `Bits(n)`: \(n\) bits in LSB-first canonical packing;
- `Words(w,n,endian)`: \(n\) unsigned words of width \(w\in\{8,16,24,32,48,64\}\);
- `Mask(n)`: \(n\) Boolean values.

Every node declares its output type and exact logical length. The evaluator
returns either that exact value or a typed error; partial output is never a
successful decode.

A graph is

\[
G=(D,r,T,n),
\]

where \(D\) is a topologically ordered definition table, \(r\) the root node,
\(T\) the output coordinate interpretation and \(n\) the original byte count.
The archive is valid iff

\[
\operatorname{Evaluate}(D,r,T)=X,\qquad |X|=n,
\]

and the SHA-256 stored in the header matches \(X\).

## 2. Exact arithmetic

- Unsigned word arithmetic defaults to modulo \(2^w\).
- Signed values use two's-complement interpretation with an explicitly stored
  width; conversion back to bytes is the identical bit pattern.
- Integer division stores a rounding rule: floor, ceiling, toward-zero or
  nearest-ties-to-even. Division by zero is invalid.
- Fixed-point values store signed integer mantissa and scale. Multiplication
  uses checked widened intermediates followed by the stored rounding rule.
- Rational nodes store reduced signed numerator and positive denominator.
- Shifts at least the word width are invalid unless the opcode explicitly
  defines a zero result.
- Every overflow policy is either checked-error or explicit wrapping; no
  platform default is used.

Floating-point evaluation is forbidden in the archive semantics.

## 3. Residual composition

For equal-length values, a correction layer declares one of:

\[
\begin{aligned}
X&=P\oplus R,\\
X&=P+R\pmod{2^w},\\
X&=P-R\pmod{2^w},\\
X&=\operatorname{Patch}(P,I,V).
\end{aligned}
\]

The correction \(R\) is itself a graph node. Recursion ends at `LITERAL` or an
exact generator. Profile limits bound correction depth, dependency count,
work and memory.

For a residual \(R_j\), the encoder evaluates a finite candidate set
\(\mathcal P_j\) and chooses between a literal leaf and another layer:

\[
C(R_j)=\min\left(
L(\operatorname{LITERAL}(R_j)),
\min_{P\in\mathcal P_j}[L(P)+C(R_j\ominus P)]
\right).
\]

Every term is the actual canonical serialisation length in its complete
parent context. Estimates may rank candidates but never make the final choice.

## 4. Literal safety

For every finite byte string, the canonical v1 block partition whose roots are
`FILE(LITERAL(block))` is defined (with the unique zero-block form for empty
input). The encoder always materialises that complete archive candidate first
and treats its length as the initial upper bound. A procedural winner is
emitted only if its complete archive is shorter, or if it ties and wins the
normative tie-break.

Thus, under an identical header/index policy:

\[
L(\operatorname{MathSVG}(X))
\le L(\operatorname{LiteralArchive}(X)).
\]

This is not a guarantee relative to an external codec.

## 5. DAG constraints

- Definition IDs are dense from zero.
- A definition may reference only a lower ID.
- The body may reference any definition.
- The graph must be acyclic by construction.
- A reference carries only a definition ID and a bounded canonical parameter
  delta.
- Definition, reference and delta bytes are included in the archive cost.
- Decoder limits bound definitions, nodes, edges, depth, fan-out, parameters,
  generated bytes and aggregate evaluator work.

## 6. Cost model

For a fully serialised archive \(A(G)\):

\[
L(G)=|A(G)|.
\]

The accounting identity is:

\[
\begin{aligned}
|A|={}&L(\text{header})+L(\text{coordinate})+
L(\text{topology})+L(\text{definitions})\\
&+L(\text{references})+L(\text{parameters})+
L(\text{residual layers})+L(\text{literal leaves})\\
&+L(\text{entropy metadata})+L(\text{index})+L(\text{footer}).
\end{aligned}
\]

The final comparator serialises complete candidates. An oracle or search
heuristic may cache descriptors and sizes, but the selected winner is
re-encoded and its measured byte count must equal the predicted exact cost.

Tie-break for equal byte length:

1. lower bounded decode work;
2. lower bounded decode memory;
3. fewer nodes;
4. fewer dependencies;
5. lexicographically smaller opcode sequence;
6. lexicographically smaller canonical parameter payload;
7. lexicographically smaller complete canonical payload as the final
   total-order fallback.

## 7. Search and pruning

The candidate generator is deterministic. Candidate IDs are assigned after a
canonical sort independent of thread scheduling.

Pruning events are:

- `SAFE_PRUNE`: admissible lower bound is at least the best complete upper bound;
- `HEURISTIC_SKIP`: deterministic profile policy omitted a candidate;
- `BUDGET_STOP`: a declared work or memory budget was reached.

Only the first preserves exact optimality inside the enumerated graph. Oracle
samples quantify regret for the other two.

## 8. Procedural metrics

Every archive reports:

- coordinate, graph, definition, reference, parameter, residual and literal bytes;
- node/shared-node counts and residual depth;
- function-reconstructed and literal-reconstructed byte counts;
- bytes saved by coordinates, sharing, residual recursion and symbolic search;
- entropy-coder bytes saved separately;
- search time per saved byte.

For non-empty input:

\[
\text{procedural coverage}
=1-\frac{\text{literal reconstructed bytes}}{\text{original bytes}}.
\]

Procedural gain is the literal-only archive length divided by the native
procedural archive length. A gain due only to entropy coding literal bytes is
reported as entropy gain, not procedural gain.
